## 1.实验目标：
配置 SSH 服务，实现从宿主机到虚拟机的免密登录，并使用 SCP/rsync 传输文件
## 2.实验环境：
| 项目 | 配置 |
|------|------|
| 宿主机操作系统 | Windows 11 |
| 虚拟机操作系统 | Ubuntu Server 22.04.5 LTS |
| SSH 服务 | OpenSSH Server（虚拟机内，默认端口 22）|
| SSH 客户端 | Windows 自带 OpenSSH Client / Git Bash |
| 认证方式 | 密钥认证（ed25519 算法） |
| 文件传输工具 | scp（系统自带）、rsync 3.2.7（手动安装） |
## 3.核心操作记录：
（1）启用 SSH 服务：在虚拟机中执行 sudo systemctl start ssh 和 sudo systemctl enable ssh
![启用 SSH 服务](./images/启用ssh服务.png)
（2）生成密钥对：在宿主机（Windows）终端执行 ssh-keygen -t ed25519
![生成密钥对](./images/生成密钥对.png)
（3）复制公钥：执行 ssh-copy-id vboxuser@虚拟机IP，将公钥添加到虚拟机的 ~/.ssh/authorized_keys 文件中
（4）测试免密登录：执行 ssh vboxuser@虚拟机IP，确认无需密码即可登录
（5）测试文件传输：使用rsync或scp命令，将本地 test.txt 文件传输到虚拟机 /tmp/

## 5.知识总结
| 知识点 | 核心内容 |
|--------|----------|
| SSH 协议 | 加密网络协议，默认端口 22，用于安全远程登录 |
| SSH 服务管理 | `sudo systemctl start/status/enable ssh` |
| SSH 密钥认证 | `ssh-keygen -t ed25519` 生成密钥对，`ssh-copy-id` 复制公钥 |
| 免密登录 | 公钥添加到 `~/.ssh/authorized_keys`，实现免密登录 |
| SCP 文件传输 | `scp local_file user@ip:/remote_path` |
| rsync 文件同步 | `rsync -avz -e ssh --delete source/ user@ip:/target/` |
## 6.出现问题：
| 问题描述 | 原因分析 | 解决方案 |
|----------|----------|----------|
| SSH 连接 `Connection refused` | 虚拟机未安装或未启动 SSH 服务 | `sudo apt install openssh-server -y`，`sudo systemctl start ssh` |
| `ssh-copy-id` 失败，提示 `Permission denied` | 虚拟机 `~/.ssh/authorized_keys` 文件不存在或权限错误 | 手动创建 `~/.ssh/authorized_keys`，设置权限 `chmod 600`，粘贴公钥 |
| `git clone` 主题超时（`Connection was reset`） | GitHub 在国内访问不稳定 | 使用 Gitee 镜像源，或手动下载 ZIP 文件 |
| `git push` 报错 `src refspec main does not match any` | 本地分支名是 `master`，推送时指定了 `main` | `git branch -M master main` 重命名分支，或 `git push origin master` |
| Git 仓库中 `themes/landscape` 显示为子模块（带箭头图标） | 克隆主题时未删除其中的 `.git` 文件夹 | 删除 `themes/landscape/.git`，`git rm --cached themes/landscape`，重新 `git add` |
