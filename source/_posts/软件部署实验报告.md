## 1.实验目标:
通过 GitHub Actions 实现 git push 后自动构建,通过编写脚本实现一键式半自动化部署。
## 2.实验环境：
| 项目 | 配置 |
|------|------|
| 部署目标 1（公网） | GitHub Pages（https://h1145gg.github.io） |
| 部署目标 2（内网） | 虚拟机 Nginx（http://192.168.56.101IP） |
| Web 服务器（虚拟机） | Nginx 1.18.0 |
| 网站根目录（虚拟机） | /var/www/html/ |
| 部署方式（自动化） | GitHub Actions（仅限 GitHub Pages） |
| 部署方式（手动脚本） | deploy.bat（封装 hexo generate + rsync） |
| CI/CD 配置文件 | .github/workflows/pages.yml |
| 半自动化脚本 | deploy.bat（双击运行，完成生成+同步） |
## 3.核心操作记录：
（1）部署 Nginx：在虚拟机中执行 sudo apt install nginx -y，并修改目录权限 sudo chown -R vboxuser:vboxuser /var/www/html/
（2）配置 CI/CD：在项目根目录创建 .github/workflows/pages.yml，编写 build、deploy-to-github-pages两个任务
（3）配置脚本：
  @echo off
  echo 当前目录: %cd%
  echo 正在生成静态文件...
  call hexo generate
  if %errorlevel% neq 0 (
    echo Hexo generate 失败，错误码: %errorlevel%
    pause
    exit /b %errorlevel%
  )

  echo 正在同步到虚拟机...
  call scp -r public/* vboxuser@192.168.56.101:/var/www/html/
  if %errorlevel% neq 0 (
    echo SCP 同步失败，错误码: %errorlevel%
    pause
    exit /b %errorlevel%
  )

  echo 部署完成！
  pause
（4）推送触发：
执行 git push origin main，触发自动化流水线
（5）双击deploy.bat脚本，自动化部署
（6）验证双重部署：
访问 https://h1145gg.github.io 和 http://192.168.56.101IP

## 5.知识总结
| 知识点 | 核心内容 |
|--------|----------|
| Nginx Web 服务器 | 安装 `sudo apt install nginx -y`，启动 `sudo systemctl start nginx` |
| 网站根目录 | `/var/www/html/`，需修改权限 `sudo chown -R vboxuser:vboxuser /var/www/html/` |
| 手动部署脚本 | `deploy.bat` 封装 `hexo generate` + `rsync`，实现一键同步 |
| CI/CD | GitHub Actions 自动构建并部署到 GitHub Pages |
| GitHub Actions 工作流 | `.github/workflows/pages.yml` 定义构建和部署任务 |
| 混合部署策略 | GitHub Pages（自动化）+ 虚拟机（半自动化脚本） |
## 6.出现问题
| 问题描述 | 原因分析 | 解决方案 |
|----------|----------|----------|
| Nginx 部署后显示默认欢迎页 | `/var/www/html/` 目录权限不足 | `sudo chown -R vboxuser:vboxuser /var/www/html/` |
| GitHub Actions `deploy-to-vm` 连接超时（`Connection timed out`） | 虚拟机 IP 为内网地址，GitHub 服务器无法直接访问 | 放弃 CI/CD 部署虚拟机，改用本地脚本 `deploy.bat` 手动同步 |
| GitHub Actions 显示 `Unable to resolve action easingthemes/ssh-deploy@v5` | Action 版本 `v5` 不存在或已更新 | 使用具体版本号 `@v4.0.5` |
| GitHub Actions `build` 任务等待 Runner 超过 10 分钟 | 免费 Runner 资源紧张，任务排队 | 取消并重新运行工作流，或避开高峰期提交 |
| GitHub Pages 部署后页面空白 | `themes/` 目录为空或主题未正确安装，导致构建生成空白 `index.html` | 确保 `themes/landscape` 主题已正确安装，且 `_config.yml` 中 `theme: landscape` |
| 本地 `public/index.html` 空白 | `hexo generate` 时 `No layout` 警告 | 检查 `themes/` 目录是否有有效主题，确认 `_config.yml` 中 `theme` 字段与主题文件夹名称一致 |
## 7.心得体会
自动化与半自动化的权衡：GitHub Actions 实现了 GitHub Pages 的完全自动化部署，但由于网络环境限制，虚拟机的部署采用了 deploy.bat 脚本的半自动化方案。这让我认识到，在实际开发中，技术方案需要灵活变通，完全自动化不一定总是可行或必要的
